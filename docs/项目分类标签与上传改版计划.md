# ICTHub 项目分类、标签与上传改版计划

> 状态：首期已实施，待生产验收  
> 日期：2026-07-22  
> 范围：React 前端、Rust API、SQLite 数据库与项目封面服务层

## 1. 五类主分类

每个正式项目必须且只能选择一个主分类：

| 主分类 | 判断规则 |
| --- | --- |
| 传统软件 | Web、App、管理系统、日常工具、基础设施，且 AI 不是核心能力 |
| 智能硬件 | 硬件、嵌入式、物联网、机器人及软硬结合项目 |
| AI 软件 | 算法模型、AI 原生应用、大数据分析，AI 或数据是核心能力 |
| 数字媒体 | 动画、游戏、交互设计、3D、VR、数字展陈 |
| 研究成果 | 论文、实验研究、方法研究、调研报告 |

比赛名称不再作为主分类。前后端均使用固定枚举校验，首页筛选只展示“全部”和以上五类。

## 2. 标签体系

项目可以关联多个正式标签。SQLite 保留原有 `project_tags.tag` 文本快照，并增加 `tag_definition_id` 指向标签定义，避免破坏旧数据和旧查询。

系统初始化三个比赛标签：

- 国创赛（互联网+）
- 计算机设计大赛
- 智能应用技术大赛

同时初始化以下分组：

- 比赛：三个比赛标签；
- 技术：大数据、人工智能应用、LLM/Agent、计算机视觉、NLP、物联网、嵌入式、机器人、Web、移动端、3D/VR；
- 特征：软硬结合、AI核心、AI增强、非AI、开源项目；
- 领域：校园服务、教育、农业、医疗、文旅、工业、科研辅助；
- 来源：比赛项目、实验室建设、课程项目、日常工具、个人探索、对外服务。

## 3. 标签权限

- 实验室成员可以查询并选择启用中的正式标签；
- 实验室成员不能创建正式标签，可以提交标签建议；
- Feiyue 管理员和超级管理员可以新增、重命名、调整分组和排序、停用、重新启用及合并同义标签；
- 标签停用不会删除历史项目关系；
- 标签合并会把项目关系迁移到目标标签，并停用来源标签。

前端提供管理员标签维护页 `/admin/tags`，上传表单内也提供管理员快速新增标签入口。

## 4. 实验室成员上传与访问权限

权限判断继续复用 Feiyue `/auth/me` 返回的 `isLabMember`、`isSuperAdmin`、`isAdmin` 和 `role`：

- 未登录：跳转登录，Rust API 返回 401；
- 已登录但不是实验室成员：列表、详情和上传入口均不可访问，显示“当前账号尚未开通实验室权限，请联系管理员”，Rust API 返回 403；
- 实验室成员：可以读取列表和详情、上传、更新、归档及使用 Codex 一键导入；
- 超级管理员：拥有成员权限和标签管理权限；
- 标签词表管理只允许管理员或超级管理员。

旧 URL `/admin/projects/new` 继续保留，但界面统一使用“上传项目”“上传”“正在上传”等文案。

## 5. Agent 封面规则

封面候选顺序为：

1. 成员手动覆盖；
2. 项目截图或海报；
3. 视频封面；
4. PPT 首页；
5. GitHub 社交预览；
6. 文档代表图片；
7. 无可用图片时使用确定性文字封面。

首期不调用复杂生图模型。Rust `covers` 服务层根据项目名、简介、主分类、标签和资源生成：

- `cover_title`：4～8 个汉字；
- `cover_subtitle`：最多 20 个汉字；
- `cover_keywords`：最多三个；
- `cover_tone`：传统软件 `slate`、智能硬件 `amber`、AI 软件 `violet`、数字媒体 `cyan`、研究成果 `emerald`；
- `confidence`：图片候选 0.92，文字 fallback 0.74，人工覆盖 1.0。

前端上传页实时预览封面，可识别常见图片扩展名，并允许手动修改标题、副标题、关键词和色系。服务层保持确定性，后续可替换为真实模型实现。

## 6. SQLite 增量变更

迁移文件：`backend/migrations/0003_categories_tags_covers.sql`。

新增 `tag_definitions`：

```text
id, name, group_name, color, sort_order, is_active, merged_into_id,
created_by_sid, created_at, updated_at
```

新增 `tag_suggestions`：

```text
id, name, group_name, reason, status, created_by_sid,
reviewed_by_sid, created_at, updated_at
```

`projects` 增加：

```text
classification_status, legacy_primary_category,
cover_mode, cover_resource_id, cover_title, cover_subtitle,
cover_keywords, cover_tone, cover_confidence, cover_generated_at
```

`project_tags` 增加可空字段 `tag_definition_id`，原 `tag` 字段与主键不变。迁移会把历史自由标签导入“历史”分组，并回填定义 ID。

## 7. 旧数据迁移规则

| 旧分类 | 迁移结果 |
| --- | --- |
| 互联网+ | 增加“国创赛（互联网+）”标签；按项目名和简介规则重新判断主分类 |
| 计算机设计大赛 | 增加同名比赛标签；按项目名和简介规则重新判断主分类 |
| 论文 | 主分类迁移为“研究成果” |
| 工具项目 | 主分类迁移为“传统软件” |
| 其他 | `classification_status` 设为 `pending`，从正式列表隐藏，等待管理员确认 |

原分类写入 `legacy_primary_category`。由于旧表的 `primary_category` 为 `NOT NULL`，“其他”记录暂存“传统软件”作为数据库占位值，但在 `pending` 状态下不作为正式分类发布。

## 8. API 变更

```text
GET    /api/v1/projects                         实验室成员
GET    /api/v1/projects/{slug}                  实验室成员
POST   /api/v1/projects                         实验室成员
PUT    /api/v1/projects/{slug}                  实验室成员
DELETE /api/v1/projects/{slug}                  实验室成员
GET    /api/v1/tags                             实验室成员
POST   /api/v1/tags                             管理员
PATCH  /api/v1/tags/{id}                        管理员
POST   /api/v1/tags/{id}/merge                  管理员
POST   /api/v1/tag-suggestions                  实验室成员

POST   /api/v1/projects/{slug}/cover/generate   实验室成员
PATCH  /api/v1/projects/{slug}/cover            实验室成员
```

项目列表响应增加最多三个标签与封面字段；项目详情继续返回状态、负责人、来源、资源和锐评。

## 10. 验收标准

- 项目列表一级分类只出现五个正式值；
- 比赛名称仅作为标签；
- 三个初始化比赛标签存在；
- 普通成员不能创建正式标签，但可以提交建议；
- 管理员可以维护和合并标签；
- 匿名列表返回 401，非成员列表与详情返回 403；
- 实验室成员可以读取列表/详情并上传项目；
- 无图片时产生合规文字封面，有图片时优先选择图片候选；
- 项目卡片只突出封面、项目名、简介、主分类、最多三个标签和最高奖项；
- 100% 浏览器缩放下正文、分类、标签与表单文字清晰，无横向溢出；
- `pnpm typecheck`、`pnpm lint`、`pnpm test:run`、`pnpm build`、`cargo fmt --all -- --check`、`cargo test --workspace` 全部通过后才部署。
