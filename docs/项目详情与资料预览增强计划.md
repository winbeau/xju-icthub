# ICTHub 项目详情与资料预览增强计划

## 1. 目标

把当前“资源名称列表 + 打开/待补充”升级为简洁的项目资料工作区，使实验室成员可以在项目详情和 Codex 导入确认阶段直接预览项目材料。

首期必须支持：

- PDF：多页连续浏览、缩放、适应宽度、下载；
- DOCX：浏览器内高保真渲染、缩放、下载；
- HTML PPT：在隔离环境内运行其 HTML、CSS、JavaScript 和相对路径资源，支持全屏与新窗口演示；
- 图片和文本：作为低成本补充预览；
- 无法预览或加载失败时明确降级为下载，不出现白屏。

本次保持 ICTHub 的简洁项目详情风格，不把页面改造成字段密集的后台，也不迁入 Feiyue 资料库的完整上传、建文件夹、重命名和拖拽管理系统。

## 2. 现状结论

### 2.1 Feiyue 可复用能力

`xju-feiyue` 的资料页已经形成一套成熟预览基础设施：

- `MaterialDetailView.tsx`：使用 `react-resizable-panels` 实现左侧文件树、右侧预览的可调分栏；
- `PreviewPane.tsx`：按文件类型懒加载 viewer，使用 Suspense、ErrorBoundary 和下载卡兜底；
- `PdfViewer.tsx`：基于 `pdfjs-dist`，支持多页懒渲染、HiDPI、适宽、30%～300% 缩放、竞态取消和缓存；
- `DocxViewer.tsx`：基于 `docx-preview`，保留 Word 页面版式并支持缩放；
- `ImageViewer.tsx`、`CodeViewer.tsx`：图片缩放和文本/代码预览；
- `usePreviewZoom.ts`、`useDragScroll.ts`：稳定的缩放状态和平移交互；
- `fileTypes.ts`、`FileTypeIcon.tsx`：扩展名、预览类型和视觉图标的统一分发；
- `globals.css` 中的 `.docx-wrapper` 修订：去除 `docx-preview` 默认灰底和过重阴影。

以上前端组件可以迁入 ICTHub 后做小幅适配。PDF、DOCX、图片、代码 viewer 不依赖 Feiyue 业务状态，适合复用。

### 2.2 不应原样迁移的部分

- Feiyue 文件树包含建文件夹、重命名、删除、拖拽排序和上传等完整资料管理能力，超出 ICTHub 当前详情页所需；
- Feiyue 的预览文件位于公开静态 `/uploads`，viewer 可以直接 `fetch(url)`；ICTHub 项目资料只允许实验室成员访问，必须携带鉴权或使用短期预览令牌；
- Feiyue 出于存储型 XSS 防护明确拒绝 `.html/.htm` 上传，因此没有 HTML PPT viewer；
- HTML PPT 不能直接放在 `icthub.top` 同源页面内运行，否则附件脚本可能读取主站页面、Token 或调用主站 API。

### 2.3 ICTHub 当前根因

当前问题不只是展示样式：

1. `ImportProjectPage.editorDraft()` 把导入产物转成项目资源时统一写入 `url: null`；
2. 导入资源使用 `.slice(0, 12)`，项目材料较多时会静默丢弃后续条目；
3. `resources.object_key`、`source_name` 已存在，但 Rust 项目读写层没有使用；
4. 导入文件仍位于 `uploads/imports/{job_id}/extracted`，确认项目时没有复制到永久项目存储；
5. 项目详情只有扁平资源行，没有资源内容端点、预览鉴权和 viewer；
6. HTML PPT 目前只识别了入口 `index.html`，尚未把它的 CSS、JS、图片等整个目录视为一个可运行资源包。

因此必须先打通“导入产物 → 永久资源 → 鉴权读取”链路，再做前端预览。只改 UI 无法解决“待补充”。

## 3. 页面设计

### 3.1 项目详情结构

项目标题区继续保持现状，保留项目名、主分类、状态、标签、来源者和负责人。简介、奖项和备注压缩为紧凑信息区。

其下新增“项目资料”工作区：

```text
┌─────────────────────────────────────────────────────────────┐
│ 项目资料                                      下载 / 全屏   │
├──────────────────┬──────────────────────────────────────────┤
│ 项目链接          │                                          │
│ 项目文档          │              当前文件预览                │
│  · 需求文档.pdf   │                                          │
│  · 设计文档.docx  │       PDF / DOCX / HTML PPT Viewer       │
│ 项目 PPT          │                                          │
│  · ppt-html 演示  │                                          │
│ 展示视频          │                                          │
└──────────────────┴──────────────────────────────────────────┘
```

- 桌面端：左侧 280～360px 资源导航，右侧预览区；使用可拖动分栏；
- 项目资源仍按“项目链接、项目文档、项目 PPT、展示视频、补充材料”分组，不展示 HTML PPT 内部的运行时文件；
- 资源行只显示图标、文件名、类型和大小，选中态使用轻背景，不增加大面积装饰；
- 初次进入默认选中第一项可预览资源，优先级为 HTML PPT、PDF、DOCX、图片、文本；
- GitHub、百度网盘等链接仍在新窗口打开，不进入内部 viewer；
- 移动端取消双栏，资源列表在上，选中后进入全屏预览层；
- 预览失败、格式不支持或资源缺失时显示明确下载卡。

### 3.2 Codex 导入页

导入结果的“材料清单”复用同一个资源导航和 PreviewPane：

- 点击 PDF、DOCX、图片或 HTML PPT 时，右侧/弹窗立即预览；
- 预览的是导入任务临时产物，不要求先创建正式项目；
- 人工确认时可以勾选是否收录该资源；
- 不再截断为前 12 项；内部运行文件由资源包归并逻辑处理，不作为 100 多条独立项目资源写入。

## 4. 资源模型与 SQLite 变更

沿用现有 `resources` 表，并启用已有的 `object_key`、`source_name`。新增字段建议如下：

```text
resources:
- mime_type            TEXT
- size_bytes           INTEGER
- display_path         TEXT
- preview_kind         TEXT
- entry_path           TEXT
- source_import_job_id TEXT
- source_artifact_id   TEXT
- sha256               TEXT
```

字段语义：

- `object_key`：相对项目资源根的永久存储键，不存服务器绝对路径；
- `display_path`：用户看到的精简路径；
- `preview_kind`：`pdf | docx | html_bundle | image | text | video | unsupported`；
- `entry_path`：HTML 资源包的入口，例如 `index.html`；普通文件为空；
- `source_import_job_id/source_artifact_id`：保留来源，便于审计和重复提交幂等；
- `sha256`：校验复制结果、去重和下载完整性。

现有只有外链或 `url IS NULL` 的资源保持兼容，不修改旧记录内容。旧资源可以后续由管理员重新关联导入产物。

## 5. 永久存储链路

### 5.1 存储布局

```text
backend/uploads/projects/{project_id}/resources/{resource_id}/
  ├─ original.pdf
  └─ bundle/
      ├─ index.html
      ├─ assets/app.js
      ├─ assets/style.css
      └─ images/cover.png
```

- 单文件资源保存原扩展名，展示名仍存数据库；
- HTML PPT 以目录资源包保存，入口及所有相对资源保持原目录结构；
- 不执行、编译或改写用户源码；
- 禁止符号链接、绝对路径、`..`、设备文件和越界读取；
- 项目归档先不删除物理资源，后续独立设计清理和恢复策略；
- `uploads/projects` 必须纳入生产备份。

### 5.2 导入确认

新增后端确认接口，由 Rust 负责持久化，不再由前端拼出一组 `url: null` 资源：

```text
POST /api/v1/import-jobs/{job_id}/commit
```

请求包含项目字段和选中的逻辑资源 ID。后端流程：

1. 校验实验室成员身份和导入任务归属；
2. 将导入 artifact 归并成逻辑资源；
3. HTML PPT 以入口所在目录为 bundle root，复制完整子树；
4. 复制到同文件系统的 `.staging/{operation_id}`；
5. 计算哈希、MIME、大小和入口路径；
6. SQLite 事务写入项目及资源记录；
7. 原子移动 staging 目录到最终位置；
8. 失败时清理 staging，重复请求通过来源字段保持幂等。

导入任务目录不能作为正式项目的长期存储，后续可以按保留周期清理，不影响已确认项目。

## 6. 资源 API

### 6.1 正式项目资源

```text
GET /api/v1/projects/{slug}/resources
GET /api/v1/projects/{slug}/resources/{resource_id}/content
GET /api/v1/projects/{slug}/resources/{resource_id}/download
POST /api/v1/projects/{slug}/resources/{resource_id}/preview-token
```

- 全部接口验证实验室成员身份；
- `content` 用于 PDF、DOCX、图片和文本预览，支持正确 MIME、Content-Length、ETag，并按需要支持 Range；
- `download` 强制 `Content-Disposition: attachment`，文件名使用 RFC 5987 编码；
- `preview-token` 仅用于 HTML PPT，返回短期、单资源、只读能力令牌；
- 外链资源不经过文件接口，仍直接返回其 URL。

### 6.2 导入任务临时预览

```text
GET  /api/v1/import-jobs/{job_id}/artifacts/{artifact_id}/content
POST /api/v1/import-jobs/{job_id}/artifacts/{artifact_id}/preview-token
```

仅任务创建者和超级管理员可访问，路径必须由数据库 artifact 记录反查，禁止把客户端路径直接拼到文件系统。

## 7. HTML PPT 安全预览

### 7.1 独立预览域

建议新增：

```text
https://preview.icthub.top/
```

该域只服务 HTML 资源包，不承载登录、主站 API 或主站 Cookie。Cloudflare Tunnel/Nginx 将其转发到 ICTHub 后端的受限 bundle 路由。

主站使用：

```html
<iframe
  sandbox="allow-scripts allow-same-origin allow-presentation"
  referrerpolicy="no-referrer"
  allow="fullscreen"
/>
```

由于 iframe 与主站跨域，即使允许 HTML PPT 的脚本运行，也不能读取 `icthub.top` 页面、localStorage 或调用带主站凭据的接口。

### 7.2 响应约束

- 令牌有效期建议 5～15 分钟，只绑定一个资源包；
- 入口和子资源都必须位于同一 bundle root；
- 响应增加严格 CSP，默认只允许包内脚本、样式、图片、字体和媒体；
- 禁止表单提交、顶层跳转、弹窗、外部网络连接和主站嵌入之外的 frame ancestor；
- 主站域不直接以内联方式返回 HTML 附件；
- 下载 HTML 包时仍使用 attachment；
- 记录预览令牌签发与拒绝日志，但不记录令牌原文。

首期不保证依赖外部 CDN、远程 API 或浏览器扩展的 HTML PPT 完整运行。页面应提示“外部依赖已被安全策略阻止”，不得为兼容性放开主站权限。

## 9. 格式支持矩阵

| 类型 | 首期行为 | 实现 |
| --- | --- | --- |
| PDF | 在线预览 | pdfjs，多页懒渲染、缩放、适宽 |
| DOCX | 在线预览 | docx-preview，高保真页面布局 |
| DOC | 下载 | 首期不引入 LibreOffice 服务端转换 |
| HTML PPT | 在线预览 | 独立预览域 + sandbox iframe + bundle token |
| PPTX/PPT | 下载；保留转换扩展位 | 后续可用 LibreOffice 转 PDF 后复用 PdfViewer |
| PNG/JPG/WebP | 在线预览 | 图片 viewer |
| TXT/MD/常见源码 | 在线预览 | 文本限制 + highlight.js |
| MP4/WebM | 浏览器原生播放 | 鉴权短期 URL + Range |
| ZIP/其他 | 下载 | 不在项目详情内展开执行 |

## 10. 实施阶段

### P0：资源契约与永久存储

- SQLite 迁移；
- Rust 资源服务层；
- 导入 artifact 归并；
- 导入确认时永久化资源；
- 资源 content/download API；
- 删除 `.slice(0, 12)` 与 `url: null` 提交方式。

退出条件：确认项目后 PDF/DOCX 等文件具有永久 object key，服务重启和清理导入任务后仍能下载。

### P1：Feiyue 预览栈迁移

- 完成资源工作区、桌面分栏和移动端预览层；
- 项目详情接入 PDF、DOCX、图片、文本预览。

退出条件：Kylin 项目的 PDF/DOCX 可在详情页打开，失败时稳定降级下载。

### P2：HTML PPT 资源包

- 识别 `ppt-html/index.html` 等入口；
- 按目录归并资源包，保留全部相对资源；
- 实现短期 preview token；

退出条件：现有 Kylin `ppt-html` 可以加载 CSS/JS/图片并翻页，无法访问主站身份数据。

### P3：导入页预览与选择

- 导入任务临时资源预览 API；
- 材料清单可点击预览；
- 逻辑资源选择、取消收录和默认命名；
- 人工确认后调用后端 commit 接口。

退出条件：上传 ZIP 后，无需创建项目即可预览文档和 HTML PPT；确认后同一资源在正式详情继续可用。

### P4：测试、性能和部署

- 单元、集成、端到端与安全测试；
- viewer 懒加载与 bundle 大小检查；
- 数据备份/恢复验证；
- huawei2 部署和 Cloudflare/Nginx 验证；
- 不修改或重启 Feiyue 业务与配置。

## 12. 风险与边界

- HTML PPT 是主动内容，必须完成独立预览域后才能上线，不能临时用主站同源 iframe；
- DOCX 浏览器渲染不等同于 Microsoft Word，复杂宏、嵌入对象和特殊字体可能降级；
- PPTX 首期不直接预览，避免为单一格式引入常驻 LibreOffice 服务；
- 大 PDF 和视频需限制并发、支持懒加载/Range，不能一次性塞入内存；
- HTML bundle 可能包含大量小文件，需要文件数、总大小和单文件上限；
- viewer 代码可以从 Feiyue 复制，但后续在 ICTHub 内独立维护，不让两个仓库形成运行时耦合；
- 本计划只修改 ICTHub。实施时严禁改动 Feiyue 业务代码和 Nginx 配置。

## 13. 推荐实施顺序

先完成 P0，再迁移 viewer。P0 是当前“待补充”的根本修复；P1 解决文档体验；P2 单独完成 HTML PPT 安全闭环；P3 才把同一套能力接回 Codex 导入流程。

建议按四个可回滚提交推进：

1. `resource persistence and authenticated content API`
2. `reuse feiyue document preview workspace`
3. `add isolated html presentation preview`
4. `preview and commit codex import resources`
